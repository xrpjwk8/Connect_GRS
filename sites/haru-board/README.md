# Connect owner web

Connect 점주용 장부·월간 달력 MVP. 기존 RN 앱과 같은 Supabase 개발 프로젝트를 사용합니다. 정적 HTML/CSS/ES modules이며 `dist/`를 게시합니다.

## 실행

```sh
npm ci
npm run configure
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
npm test
```

공개 설정은 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY` 환경 변수 또는 같은 저장소의 `../../ConnectRN/.env.local`에서 가져옵니다. publishable key만 사용합니다. 브라우저용 SDK 2.117.3은 `dist/vendor/`에 포함하고 라이선스를 동봉했습니다. 외부 CDN은 사용하지 않습니다.

## 구현

- Connect 기존 점주 이메일 OTP 로그인, owner 역할 및 매장 소유권 확인
- 날짜별 장부, 상태 필터·검색, 우측 상세 / 모바일 모달
- 월간 42칸 달력, 날짜별 확정 예약·인원·대기·내부 일정
- 앱 공통 RPC: 수락·거절·취소·완료, 중복 방지 UUID를 사용하는 수동 예약
- 일반 내부 일정 CRUD (`owner_schedule_events`), RLS 적용
- 앱 공통 시간 차단, 정원·영업시간·동시 예약 설정
- 활성 화면 5초 polling, 탭 복귀·온라인 복구·저장 후 갱신
- 샘플 모드: 메모리만 사용, 로그인/실제 저장과 분리, 새로고침 시 초기화

## 검증

2026-10-13 기준: 날짜/집계/이스케이프 단위 테스트 5개, 격리 PostgreSQL 테스트 24개, 기존 개발 서버 공개 API/권한 검사 8개 통과. 브라우저 테스트는 `tests/browser.cjs`, 모의 SDK 응답으로 로그인 권한·자동 갱신·오류 처리를 검증하는 테스트는 `tests/integration.cjs`입니다. 브라우저 스크립트에는 `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH`, 필요 시 `SITE_URL`을 지정할 수 있습니다.

격리 DB 검증: 저장소 루트에서 `python3 scripts/test_owner_schedule_db.py`.

## 아직 검증하지 못한 범위

실제 이메일 수신·인증과 두 계정으로 앱 신청 → 웹 수락 → 앱 상태 확인은 SMTP/테스트 계정 준비 후 확인해야 합니다. 모의 SDK 브라우저 테스트는 실제 JWT 통합 검증을 대체하지 않습니다.

내부 일정은 예약을 차단하지 않습니다. 일정과 시간 차단을 원자적으로 결합한 휴무 일정, 반복 일정, 직원 권한, 채팅은 후속 범위입니다. 현재 차단은 기존 앱의 날짜별 전체 교체 RPC를 공유하므로 여러 기기에서 같은 날짜 차단을 동시에 편집하면 마지막 저장이 적용됩니다.

## 서버

`supabase/migrations/20261013135913_owner_schedule_events.sql`이 기존 개발 서버에 적용됐습니다. 웹 전용 별도 예약 DB는 없습니다. 운영 서버로 전환할 때는 동일 스키마/RLS와 승인된 점주 계정, SMTP를 준비하고 공개 설정을 다시 생성하세요.

## 대시보드 / 요청함 / 주간 시간표

좌측 메뉴는 대시보드 → 예약 관리 → 월간 달력 → 매장 설정입니다. 대시보드는 오늘/주간의 확정 예약만 표시합니다. 예약 관리는 월 범위와 무관한 모든 pending 요청을 최신 접수순으로 읽습니다. 월간 달력은 전체 상태와 내부 일정을 유지합니다.

주간 시간표는 월–일, 매장 영업시간 내 30분 단위입니다. 확정 예약의 실제 시작·종료 시각을 겹침 비교해 정원을 합산하며, 대기/취소/완료 예약은 좌석을 점유하지 않습니다. 초록(예약 없음), 노랑(일부 예약·잔여 좌석), 빨강(만석 또는 예약 불가)으로 표시합니다. 지난 시간·점주 차단·단독 예약은 예약 불가 이유를 표시하며, 칸 선택 시 예약과 잔여 인원을 확인할 수 있습니다. 자정 경계의 인접 영업일 데이터도 조회합니다. 각 칸은 30분의 스냅샷이며 연속 예약의 최종 가능 여부는 기존 서버 RPC가 검사합니다.

`tests/dashboard.cjs`로 오늘/주간, 요청 수락 후 제거, 3단계 색상, 시간대 상세, 메뉴, 다크모드/모바일을 검증합니다. 단위 테스트는 9개입니다.

시간표 위치 변경: 주간 예약 가능 시간은 예약 관리의 요청 목록 아래에 표시합니다. 대시보드의 확정 예약 표 상단에서 좌/우 화살표로 이전/다음 날을 조회하고 ‘오늘’로 복귀합니다. 화살표를 누르면 일별 보기로 전환되며 기존 주간 보기는 유지합니다.

시간표 상세는 오른쪽 인라인 패널(좁은 화면은 아래)에서 표시하며 지난 시간은 회색으로 구분합니다. 수동 예약은 대표 예약자명(필수, 80자)과 소속/단체명(선택, 160자)을 별도로 저장합니다. 앱 접수는 가입 프로필의 필수 실명을 대표자명으로 사용합니다. 기존 예약의 이름을 자동 추정하거나 덮어쓰지 않습니다.

서버 migration `20261013145243_manual_reservation_affiliation`은 기존 수동 예약 RPC에 선택 인자를 추가하며 기존 앱 호출을 호환합니다. `scripts/test_representative_db.py`의 격리 DB 테스트 25개, 웹 패널/입력 검증, 앱 TypeScript 검사를 통과했습니다. React Native 수동 예약 화면 소스도 같은 두 입력으로 변경했습니다. 앱 바이너리 배포는 이 웹 배포에 포함되지 않습니다.
