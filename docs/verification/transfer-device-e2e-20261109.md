# 예약 양도 실기기 E2E 검증 기록

2026-11-09 KST. 두 기기에서 세 계정을 전환해 양도 핵심 흐름을 검증했다. 기기 수와 원격 제어 제약에 따른 미검증 항목은 아래에 별도 기록한다.

## 환경

- connectors-dev (`vfyxsalbvtuxurujadno`).
- 최신 Release 빌드 성공 후 iPhone 16 Pro Max와 점주 iPhone 17에 업데이트 설치했다.
- 예약자 기기: iPhone 16 Pro Max, iOS 27.0.1. 관리1자 → Apple 심사 예약자 → 관리1자 순서로 전환했다.
- 점주 기기: iPhone 17, iOS 26.6.1. Device Hub 화면 제어가 지원되지 않아 사용자가 예약 수락과 알림 표시를 직접 확인하기로 했다.
- 기기는 2대다. 예약자 계정 전환으로 검증하며, 세 계정의 푸시 동시 수신은 검증하지 않는다.

## 후속 실기기 확인 (08:22–08:29 KST)

- 사용자가 점주 기기의 신청 푸시 확인·예약 수락·양도 전 메시지 전송 요청에 `완료`로 응답했다.
- 서버 confirmed 상태와 예약자 기기의 확정 예약 표시를 확인했다.
- 예약자 기기에서 `양도 전 점주 대화 QA1109` 푸시 배너를 직접 관찰했다. 대화방에서 이 메시지와 `Booker a before transfer qa1109`의 양방향 표시를 확인했다.
- 앱에서 양도 등록 후 서버 active 상태와 `Memo qa1109 have a good gathering` 저장을 확인했다.
- 첫 등록 후 상세로 이동하지 않는 문제를 발견했다. `useNativeBack(action.busy)`의 화면 제거 방지가 성공 콜백의 replace를 막았다. TransferRegisterScreen에서 성공 ID를 상태로 보관하고 busy 해제 렌더 이후 effect에서 이동하도록 수정했다.
- 수정 후 TypeScript 검사, RN 54개 테스트, Release 빌드 통과. 테스트 중 4개가 샌드박스의 localhost listen 차단으로 실패하여 로컬 통신 허용 후 전체 54개 통과를 확인했다.
- 수정 빌드를 두 실기기에 설치했다. 원예약자에서 게시를 철회하고 원예약 confirmed 유지 및 재등록 가능을 확인했다. 재등록 후 자동으로 상세 화면에 이동해 수정 결과를 실기기에서 확인했다.
- 첫 게시 ID `fe6d160b-d581-4014-8b9d-ea75e7dd43a2`: withdrawn.
- 현재 활성 게시 ID `1fda2168-7a93-4712-9c73-c471f31fa02c`: active.
- 홈의 작은 카드(날짜만 굵게) → 전체 보기 → 전체 보드 → 상세 이동을 확인했다. 실데이터는 활성 1건이므로 최신 3건 정렬/상한의 실기기 검증은 아니다.
- 원예약자 로그아웃 완료. 인수자 이메일 인증 로그인 화면에서 사용자 입력을 기다린다. Device Hub 원격 키보드가 이메일 문자를 잘못 입력해 필드를 비우고 직접 입력을 요청했다. 인증번호 요청은 아직 전송하지 않았다.
- 추가 증빙: `transfer-device-prechat.png`, `transfer-device-home.png`, `transfer-device-registered.png`. `transfer-device-prechat-push.png`는 배너가 사라진 뒤 저장됐을 수 있어 푸시 배너 증빙으로 단독 사용하지 않는다.

## 인수자 및 점주 검증 (08:31–08:37 KST)

- 사용자가 이메일 인증으로 Apple 심사 예약자 로그인 완료. 앱 표시로 계정을 확인했다.
- 인수 계정의 알림 화면에서 푸시 활성화 성공 문구를 확인했다.
- 인수 전 상세에는 메모가 없음을 확인하고 앱의 확인 절차로 인수했다. 08:32:14 KST 완료.
- 서버에서 같은 예약 ID, confirmed, 11월 10일 17:00–17:30, 10명 유지 및 booker_id 변경, chat_epoch=1, 이전 행사 목적/요청사항 초기화를 확인했다.
- 인수 완료 상세에 `Memo qa1109 have a good gathering`이 표시됐다. 홈 게시 목록에서는 완료된 카드가 사라졌다.
- 새 예약자의 내 예약에 양도 이력 및 동일 예약 조건이 표시되고 재양도 등록 버튼은 없다.
- 새 예약자의 채팅은 처음에 비어 있었고, `Booker b after transfer qa1109`와 `양도 후 점주 대화 qa1109` 두 메시지만 표시됐다. 양도 전 두 메시지는 표시되지 않았다.
- 인수자 iOS 알림 센터에서 `예약 양도가 완료되었습니다`와 해당 일시·10명 문구를 직접 확인했다. 주변에 인증번호 이메일 알림이 있어 알림 센터 전체 화면은 파일로 저장하지 않았다.
- OS 알림 탭 연결은 Device Hub 동작으로 확정하지 못했다. 앱 내 알림 목록에서 완료 알림을 눌러 메모 포함 양도 이력으로 이동하는 것은 확인했다.
- 세 참여자의 앱 내 reservation_transferred 알림 생성 확인. 인수자와 점주 푸시 작업은 ticket, last_error 없음. 원예약자는 로그아웃 상태였으므로 푸시 작업이 없으며, 재로그인 후 앱 내 이력으로 확인할 예정이다.
- 사용자가 점주 기기의 완료 푸시/앱 알림, 동일 일시·인원 및 새 예약자 표시, 이전/새 대화 분리, 새 대화 메시지 전송, 점주 메모 비노출 요청에 `완료`로 응답했다.
- 증빙: `transfer-device-before-claim.png`, `transfer-device-claimed-memo.png`, `transfer-device-newchat-empty.png`, `transfer-device-newchat.png`.

## 원예약자 검증 및 정리 (08:41–08:44 KST)

- 원예약자 재로그인 후 앱 내 양도 완료 알림 → 완료 이력 → `양도 전 대화 기록` 연결을 확인했다.
- 이전 채팅에는 양도 전 점주/원예약자 메시지 두 개만 표시됐다. `양도 전 대화 · 읽기 전용` 안내와 비활성 입력란을 확인했다. 인수 후 새 메시지는 표시되지 않았다.
- 원예약자 알림 목록에도 새 예약자의 채팅 알림은 없었다. 원계정의 기기 푸시 연결을 다시 활성화해 성공 문구를 확인했다.
- 증빙: [원예약자 읽기 전용 이전 대화](transfer-device-original-readonly.png).
- 사용자가 점주 앱에서 해당 테스트 예약을 취소하고 `완료`로 응답했다. 읽기 전용 서버 조회에서도 예약 `0299ad1b-19b7-4a20-a5d6-801d3ddfa1fb`의 `cancelled`, `chat_epoch=1`을 확인했다. 양도/채팅 이력은 삭제하지 않았다.

## 이메일 인증 직후 약관 화면 깜빡임 수정

- 원예약자 재로그인 시 사용자가 약관 화면이 약 0.1초 표시된다고 보고했다.
- 원인: AccountAccess가 프로필 조회 완료 전에도 `session`만으로 가입 정보 및 약관을 표시했다. RootNavigator는 입력 상태 보존을 위해 이 컴포넌트를 로딩 중에도 유지한다.
- 수정: 컴포넌트의 입력 상태는 유지하면서 `ready=false` 또는 기존 프로필이 확인된 전환 구간에는 계정 확인 화면만 표시한다. 서버 조회가 완료되고 프로필이 없는 계정에만 가입 정보/약관을 표시한다.
- 예약자/점주, 로그인/가입 진입 경로 각각에 대해 조회 중 및 기존 프로필 확인 상태에서 약관/입력/가입 버튼 비노출을 검증했다. 미완료 신규 계정에는 가입 화면이 유지되는 것도 검증했다.
- TypeScript 검사, 전체 RN 테스트 55개, Release 빌드, diff 공백 검사 통과.
- 수정 Release를 두 기기에 업데이트 설치했고 예약자 기기에서 기존 로그인 유지 및 홈 실행을 확인했다.
- 수정 후 사용자가 실제 이메일 인증 재로그인에 `완료`로 응답했다. 약관 화면 재발 보고는 없었고, 별도로 인증 메일 발송 안내가 나타날 때 아래 입력창이 밀리는 현상을 보고했다.
- 추가 수정: 발송 안내 두 줄을 처음부터 같은 Text로 배치하고 발송 전에는 투명하게 숨긴다. 발송 성공 시 opacity만 바꿔 글자 크기/줄바꿈/여백을 그대로 유지한다. 긴 이메일 주소가 안내 높이를 바꾸지 않도록 중복 주소 표기는 제거했다. 숨긴 안내는 접근성 탐색에서도 제외한다.
- 추가 수정 후 TypeScript, 인증 화면 테스트 8개, diff 검사와 Release 빌드 통과. 두 기기에 업데이트 설치했다. 실기기 발송 전후 좌표 비교는 별도로 수행하지 않았다.
- 후속 요청에 따라 예약자/점주 로그인에서 비밀번호 전환 버튼, 입력 화면, 상태 및 로그인 호출을 제거해 이메일 인증번호 방식으로 통일했다. 기존 인증 화면 테스트도 이메일 인증번호 전용 흐름에 맞게 갱신했고 8개 모두 통과했다.

## 검증 범위와 제한

- 확인: 실제 앱 양도 등록/철회/재등록/인수, 홈 → 전체 보드 → 상세, 인수자 메모 전달 및 인수 전 비노출, 점주 메모 비노출(사용자 확인), 날짜·시간·인원 유지, 점주 승인 없이 완료, 세 계정 앱 알림, 점주/인수자 OS 푸시, 이전/새 대화 분리와 원예약자 읽기 전용 이력.
- 원예약자는 인수 당시 로그아웃해 OS 완료 푸시 수신은 미검증이다. 재로그인 후 앱 알림은 확인했다. 세 계정 동시 푸시 수신으로 보고하지 않는다.
- OS 알림 탭 경로는 미확인이다. 앱 내 완료 알림 탭 경로는 원예약자와 인수자 모두 확인했다.
- 실기기 활성 게시가 1건이라 최신 3건 상한/정렬을 이 E2E로 검증하지 않았다.
- 메모 50자 경계/이모지 차단, 동시 인수 경쟁, RLS 거부 등은 기존 자동 검증 범위이며 이번 실기기 정상 흐름에서 모두 재수행한 것은 아니다.
